# RealEstate — Ansible (k3s bootstrap + k8s deploy) — Blue/Green

This folder bootstraps k3s on provisioned Hetzner VMs and deploys Kubernetes manifests
from `../../k8s` using kustomize overlays.

It is designed to run mostly from the **local runner** (your laptop):
- installs k3s on remote nodes
- fetches kubeconfig to local `.kube/`
- installs addons via Helm from localhost
- applies kustomize overlays from localhost

---

## Structure

- `playbooks/site.yml` — main orchestration playbook
- `inventories/generated/` — generated by Terraform output:
    - `inventory.prod-blue.ini`
    - `inventory.prod-green.ini`
- `group_vars/` — shared vars
- `roles/`
    - `common` — base packages on all nodes
    - `k3s_server` — install k3s server, read node token
    - `k3s_agent` — install k3s agents
    - `kubeconfig` — fetch kubeconfig & patch server endpoint
    - `k8s_addons` — Helm addons:
        - ingress-nginx
        - cert-manager (with CRDs)
        - metrics-server (only if missing)
    - `k8s_deploy` — apply kustomize overlay + apply vaulted secrets + rollout restarts
    - `k8s_verify` — nodes/pods status + in-cluster health check
- `secrets/` — vaulted secret manifests applied by Ansible (prod)
- `vault-password` — local vault pass file (never commit)

---

## Prerequisites (local)

- `ansible`
- `kubectl`
- `helm`
- vault password file:
    - `infrastructure/ansible/vault-password`

Install collections:
```bash
cd infrastructure/ansible
ansible-galaxy collection install -r requirements.yml
```
## Run via Make (recommended)
App deploy BLUE:
```bash
make deploy-app-blue
# equivalent:
make deploy-app ENV=prod STACK=blue EXTRA_VARS='env=prod stack_id=blue'
```
App deploy GREEN:
```bash
make deploy-app-green
```
## What the playbook does (high-level)
1) Base packages on all nodes
2) Install k3s server
3) Install k3s agents
4) Fetch kubeconfig to local .kube/realestate-<env>-<stack>.yaml
- patches server endpoint to public IP (k3s default is 127.0.0.1)
5) Install addons via Helm (from localhost):
- ingress-nginx
- cert-manager (+ CRDs)
- metrics-server (only if missing)
6) Apply kustomize overlay:
- `k8s/overlays/<env>-<stack>`
7) Apply secrets (vaulted yaml)
8) Verify workloads and run in-cluster health check

## Troubleshooting (real incident runbook)
1) **kubeconfig points to 127.0.0.1**

k3s kubeconfig on the server often uses 127.0.0.1.
If kubectl from localhost fails:

- ensure kubeconfig was fetched
- ensure it was patched to public endpoint

Quick check:
```bash
grep -n "server:" .kube/realestate-prod-blue.yaml
```
2) **Ingress ports conflict (Traefik vs ingress-nginx)**

k3s may ship Traefik; it can conflict with ingress-nginx on 80/443. The problem occured quite often (on different machines), so I created `make` command

From repo root:
```bash
make k8s-ingress-debug
make k8s-traefik-remove
```

3) **“Ansible succeeded but site is old”**

Usually not an Ansible issue:
- mutable image tag not pulled
- LB points to the other stack

Verify inside the stack:
```bash
kubectl --kubeconfig .kube/realestate-prod-blue.yaml -n realestate \
  port-forward svc/realestate-frontend-svc 18080:80

curl -s http://127.0.0.1:18080 | head
```
4) **SSH host key mismatch after recreating servers**

Refresh known_hosts:
```bash
make ansible-known-hosts ENV=prod STACK=blue
```
